## Why This Order Matters

```
WRONG WAY (wait for bootstrap):
  "Let's bootstrap first, then document what we find"
  Problem: Bootstrap may succeed for wrong reasons
           Documentation becomes post-hoc rationalization
           No GATE principle protection

RIGHT WAY (design → bootstrap → verify):
  "Document design FIRST, bootstrap SECOND, compare THIRD"
  Benefit: Gate principle is active throughout
           Bootstrap verification against explicit authority
           Design evolves based on evidence
           Not implementation-driven specification

CRITICAL: Design authority + bootstrap verification
          is what makes the contract CANONICAL
          (not just "how it happens to work")
```
