# P0.5d.4 Minimum One-Time Semantic Producer Specification

Status: YELLOW, AUDIT/DESIGN ONLY. No producer is selected or implemented.
The input, review and lifetime contracts are defined. The executable semantic
boundary for the complete frozen closure is NOT_PROVEN; minimum contract
completion remains blocked by the obligations below. This does not reopen
P0.5d.3 candidate classification or the frozen source approval.

## Input And Identity

The producer must consume `canonical-closure.freeze.manifest` plus exactly its
37 ordered source files, with raw bytes matching every per-file digest and
commit `6e066805d55ce190bdf816f79953e36713220f7a`. Aggregate SHA256 is
`17df24ba79f4d818a994d66608f8deb61848ae54ebda339c1204f11f22fcd8f2`.
Recompute it over the ordered `<sha256>  <relative-path>\n` records. Abort on
missing, duplicate, reordered or changed inputs; do not refresh the manifest.
No ambient checkout, package index, search path or environment may silently
supply extra S source. The 37-file manifest identifies approved input bytes;
it does not establish that every runtime dependency is included.

Separately freeze producer identity/version/hash, invocation, tool dependencies,
target OS/architecture/word size/endian/ABI, runtime symbols and implementations,
toolchain versions/hashes and relevant environment values. These are trust
dependencies, not additions silently folded into the canonical source hash.
The concrete target/runtime profile is currently NOT_FROZEN.

## Two Semantic Responsibilities

The producer translates the compiler *program* in the frozen files into executable
operations. The resulting Stage1 must then execute that program on future input.
Implementing a checker inside Stage1 and checking the Stage1 source during
production are different operations. The presence of `check_source_file` in the
closure alone does not define every rule needed to translate the closure itself.

The producer must preserve canonical implementation behavior, including its
diagnostics and failure cases. It must not silently repair missing canonical
features, execute Stage1 at creation time and serialize one observed result, or
delegate future compilation to an unrecorded compiler. If faithful translation
cannot satisfy regeneration, record that conflict and stop; snapshot creation
cannot legitimately fix it by changing frozen semantics.

The ordinary modular `build` route is:

1. `modular_build_main.s:41` dispatches to `backend_elf64.build`.
2. `build:278` reads source, checks a special launcher route, then calls
   `load_source_graph`: parse -> dependency graph -> semantic check -> mono.
   `should_skip_semantic_check:2572` conditionally bypasses both check and mono
   for particular paths. The modular entry itself is not one of those paths.
3. `build` runs its safety check, lowers MIR, runs midend/SSA and ABI validations.
4. It computes writes/exit/metrics through the source interpreter with MIR
   fallback, then emits assembly from writes and exit code (`emit_asm_amd64:5403`).
   Sidecar ABI/drop/debug reports follow; they do not prove emitted semantics.

This is not a demonstrated linear Parser -> Semantic -> Mono -> MIR -> native
whole-program translation. In `lower_package_to_mir`, only `main` or a fallback
function is lowered; other function names are added to `graph.trace`. MIR also
contains `eval(op="line")` and operands with `kind="expr"`. Separately,
`mir.lower_block_graph` has drop/borrow logic, but the audited
`ir.lower.lower_main_to_mir` route does not establish that it runs that complete
path. A `borrow_ok: true` initializer is not evidence of a successful analysis.

## Semantic End

`semantic-end=NOT_PROVEN` for this full closure. Neither Semantic Analysis, MIR,
SSA nor a textual lowered view satisfies the boundary on the evidence above.
One observed local boundary is `emit_asm(writes, exit_code)`, after interpretation;
that serializes an observed behavior, not a complete executable compiler.

The required producer boundary is a complete executable representation with
resolved bindings/instances, executable bodies for every reachable declaration,
fully specified value/layout/runtime conventions, concrete control flow and
all required lifetime actions. No residual S expression may be handed to the
AOT consumer for interpretation or semantic resolution. It is valid for compiled
canonical parser/interpreter code in Stage1 to later process user source; it is
not valid for the consumer to interpret unresolved Stage1 source to create it.

After that boundary only opcode serialization, instruction selection preserving
the declared operation contract, register/stack placement under a fixed ABI,
relocation and container/link encoding are permitted. Such operations still
require correctness review; "mechanical" does not mean untrusted or trivial.
`post-semantic-encoding=NOT_PROVEN` for a concrete producer; MECHANICAL_ONLY is
the required contract, not a completed implementation claim.

## Output And Consumer Contract

Output is a complete `SSEED-TARGET-V1` snapshot, its manifest, transformation
ledger, independent review record and reproducible production transcript.
The format starts with `SSEED-TARGET-V1\n`; generator records have four fields
`op|result|operand1|operand2\n`, with empty fields represented by `_` and escaping
for backslash, pipe, LF, CR and tab. The consumer profile must specify the actual
supported opcode subset, operand meanings, limits, numeric widths and runtime
operations; a valid header or serializer opcode alone is insufficient.

`backend_registry.c:129` dispatches linux/amd64 and darwin/arm64 differently.
`native_backend.c:120` generates a Darwin runner that executes embedded IR and
also exposes bootstrap/AOT command branches. Its host-C build links seed parser
and semantic code (`native_backend.c:270`). Presence of those symbols does not
prove they execute, but a native executable is not automatically a standalone
canonical compiler. Acceptance needs call-path evidence that Stage1 build and
regeneration use canonical code, without seed source compilation or historical
launcher delegation. `backend_elf64.s:2922` also contains a special runtime-entry
launcher; that branch is not evidence for the modular-entry route.

P0.5c format eligibility remains a premise. Eligibility does not establish this
snapshot's completeness, ABI profile, consumer call path or self-regeneration.

## Review And Reproduction Contract

Maintain one structured ledger row per source declaration and generated unit:
`source_path, source_sha256, span, declaration_id, reachability, transformation_id,
input_ids, decision, canonical_rule_reference, output_ids, reviewer, evidence`.
Output IDs identify records/functions in the eventual snapshot. Account for all
37 files; omitted declarations need explicit unreachable evidence covering every
Stage1 CLI route, not merely one `return 42` run. Generic expansion creates rows;
it cannot disappear into an opaque translation step. Semantic ambiguity is a
blocking ledger item, never permission to invent a rule.

Independent review must validate bindings, specialization, effects/evaluation
order, CFG, lifetime cleanup, layouts and runtime mappings without relying solely
on the producer's own assertions. Record reviewer identity and independence,
reviewed input/output hashes, discrepancies and resolutions. Structural checks
must reject missing callees, unsupported instructions, leftover S expressions,
unaccounted source units and runtime dependencies. Hash verification binds bytes;
it cannot certify these semantic decisions.

Define stable ordering for declarations, instances, blocks, constants and records.
Two isolated productions from the same pinned inputs must produce identical
snapshot bytes. Record manual decisions as replayable instructions; replay is
not an independent derivation. Snapshot normalization cannot erase semantic
differences. No timestamps, ambient paths or random IDs in the snapshot.

Later execution acceptance must include canonical-path traces, positive and
negative semantic fixtures, dynamic input/branch behavior and return-42. Run
Stage1 -> Stage2 and Stage2 -> Stage3 from the identical source and target/runtime
profile, after disabling access to the creation producer and alternate compilers.
Require byte equality for deterministic native output; any structural/behavioral
alternative must define exclusions and comparisons in advance and report its
weaker claim. Convergence alone does not prove the first translation correct.

## Lifetime And Completion

`producer.role=ONE_TIME_BOOTSTRAP_ONLY`; long-term semantic authority is forbidden.
After accepted Stage2/Stage3 convergence the producer must not be required for
ordinary builds or regeneration. Archive its source, decisions and provenance
for review. Retaining archived evidence is not retaining build authority.
No seed expansion, independent general-purpose S compiler, or silent source
repair is authorized by this specification.

Three bounded evidence deliverables are still required before contract GREEN:

1. A complete T01-T07 semantic mapping/coverage ledger for the frozen closure,
   reconciling ordinary lowering, interpreter behavior, and the multiple ownership
   paths. It must establish the full executable boundary without source residue.
2. A frozen target/runtime profile with per-operation SSEED mapping, ABI/intrinsic
   coverage and consumer authority exclusions (T06-T08).
3. A source-backed regeneration route: explain how faithful execution of this
   frozen implementation produces a complete Stage2, given the observed
   selected-function MIR and writes/exit emission. If impossible, report the
   contradiction rather than changing the source or lowering it differently.

GREEN means these design obligations have evidence and the contract is complete;
it is not producer selection or snapshot acceptance. YELLOW means source binding
is verified but any obligation is open. RED means input/evidence validation failed.
