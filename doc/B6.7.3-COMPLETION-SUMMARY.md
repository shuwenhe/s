## Key Design Decisions

### Canonical Authority: `import_signatures.meta`

**Why this file:**
- Already maintained for function-level signatures
- Single source of truth (not multiple parallel systems)
- Can represent module structure implicitly
  - If `std.env.args` exists → `std.env` must be a module container

**Why NOT hardcode:**
- Avoids seed-only semantic authority
- Maintains compatibility with self-hosted compiler
- Enables future extensibility

### Two-Part Detection Strategy

**Part 1 - Member Type:**
- Prevents `std.env` from defaulting to "any"
- Returns "module_member" for valid module paths
- Reduces false errors

**Part 2 - Full Path:**
- Handles complete call path validation
- Directly uses import_signatures for function info
- Reuses existing lookup infrastructure
