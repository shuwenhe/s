# P0.5d.5d.1.3b — Canonical Layout Query Contract

Status: **type-input audit and query boundary defined; implementation open**. Follows [1.3a](p0.5d.5d.1.3a-layout-authority-contract.md). Audited against local `main` at `18246ecc6`. The confirmed defect is divided layout/ABI authority. This audit does not establish a machine-code miscompilation caused by `.abi` or `.abi.emit` heuristics.

## First question: what identifies a type today?

**Answer: no existing representation is sufficient as the canonical layout input.** The closest useful ingredients are the `source_file` declarations retained after semantic checking and the recursive shape of `compile.internal.ir.types.type`; neither currently supplies a resolved, unique, instantiated type identity with a declaration/field registry. `compile.internal.typesys.type_ref` is a parsed spelling, not such an identity.

| Candidate | What it carries | Why it is insufficient |
| --- | --- | --- |
| `src/s/ast.s` `source_file`, `struct_decl`, `field` | Package and item provenance, declaration order, field names and type spellings; `item_packages` tracks imported item origins. | Fields and signatures still contain strings. Identity and resolved field types are absent. It is a source for building a registry, not the query key. |
| `src/cmd/compile/internal/typesys.s` `type_ref` | A normalized string plus flags for reference, slice and array, array length text, base name and argument strings. | `same_type_ref` compares `canonical` strings. Named declaration identity, resolved children and instantiation identity are absent. Querying it would reparse spelling. |
| `src/cmd/compile/internal/semantic.s` `function_binding`, `type_binding`, `check_result` | Semantic checks and inferred type strings. `check_source_file` returns diagnostics only. | No persistent typed program or type table is handed to layout/lowering. Struct declarations are not registered as resolved field graphs here. |
| `src/cmd/compile/internal/mono/monomorphization.s` | Substitutes generic names in function/method signatures and bodies, then returns a `source_file`. | Substitution still produces strings. Generic struct declarations are retained; this pass does not produce unique instantiated struct type definitions. |

The production route in `backend_elf64.s:2492-2516` loads imported source items, runs `semantic.check_source_file`, then `mono.monomorphize_file`; build lowers the returned `source_file` to MIR at `backend_elf64.s:298`. No typed identity result crosses this handoff. A `TypeId` must be created while full declarations and import provenance remain available, and retained as an immutable side table or attached to typed IR before field definitions are erased.

## Query boundary to freeze

These are semantic signatures, not a commitment to an S struct layout or an existing implementation.

```text
resolve_type(source_type, scope, substitution, TypeRegistry)
    -> Result<CanonicalTypeRef, TypeResolutionError>

layout_of(CanonicalTypeRef, TargetDataLayout, TypeRegistry)
    -> Result<TypeLayout, LayoutError>
```

`CanonicalTypeRef` is an opaque handle to one interned semantic type. Its identity must distinguish builtin kinds; pointer/reference/slice/array constructors and their resolved children; array length; tuple component order; named declaration by package plus declaration identity; and generic arguments after substitution. Display text may be stored for diagnostics but is never the query key. The registry owns resolved struct fields in declaration order and maps each field to another `CanonicalTypeRef`. It must survive the semantic/mono → MIR/ABI handoff. Handle equality is semantic identity within one compilation; persistent serialization, if needed, requires an explicit stable identity scheme rather than raw allocation indices.

`TargetDataLayout` identifies the target's physical data rules. `layout_of` alone owns size, alignment, padding, array stride, field offsets and aggregate physical shape. `TypeLayout` must expose those facts and enough resolved component structure for later ABI classification; its exact in-memory representation remains open. Cache by `(CanonicalTypeRef, TargetDataLayout)`. Queries of unresolved generic parameters, unknown types, invalid array lengths, recursive values or unsupported unsized values return explicit errors. Recursive references terminate through pointer layout; recursive values do not silently acquire a default size.

The ABI interface accepts `TypeLayout`/type handles and a **separate** `TargetABI`. It may classify INTEGER/SSE/MEMORY and assign call-boundary locations. It cannot parse type spelling or recompute field offsets. Backend receives the resulting signature classification and may choose local frame slots and instructions. Caller and callee use the same ABI result.

### Handoff invariant

For every type used by a function signature, field access or memory operation, lowering must retain a valid canonical handle and registry entry. If a type is not resolved, the pipeline stops with an error before ABI/backend. Reconstructing a handle from a MIR/SSA `type_name` string is outside this contract.

## First implementation slice and proof obligations

1. Add a resolved type registry at the post-import semantic/monomorphization boundary. Prove that same-spelled names from different packages differ, aliases and equivalent structural types follow the intended semantic equality rules, and distinct generic instantiations have distinct identities. Keep the source declaration/field graph reachable.
2. Make `layout_of` consume only the opaque handle and target data layout. Start with primitive and pointer cases; prove queries never inspect `string type_name`. Record expected size and alignment for at least two target data layouts or explicitly restrict the first implementation to one named target.
3. Add string, arrays, structs and nested aggregate layouts from resolved child handles. Verify field order, offsets, padding, final size/alignment and array stride, including zero-sized and recursive-value rejection.
4. Feed `TypeLayout` into ABI Authority, then migrate `abiutils.s` string layout helpers. Route `.abi`/`.abi.emit` through the same ABI result before removing backend aggregate-size guesses. A text-artifact gate does not prove the machine-code edge; verify that separately when machine lowering consumes `AbiSignature`.

Gate for **1.3b contract closure**: a reviewer can identify the producer, lifetime and equality rules of `CanonicalTypeRef`, the query's target key, its error behavior and the first handoff retaining the registry. Gate for **Layout Authority implemented** is later: actual typed queries and layout tests pass, and no competing size/align/offset calculation remains on the canonical path.
