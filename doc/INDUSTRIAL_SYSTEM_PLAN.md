# S 编译器工业化系统完整实现计划

**目标**: 用 S 语言实现一个**完全独立的、生产级的编译器工具链**  
**范围**: 75K LOC，18 周，从 Lexer 到链接器到运行时  
**状态**: 进行中 (阶段 2/7)

---

## 📊 项目总体架构

```
输入源代码 (.s)
     ↓
┌─────────────────────────────────────┐
│  前端 (Frontend) - 16K LOC ✅       │
│ ├─ Lexer (词法分析)                 │
│ ├─ Parser (语法分析)                │
│ └─ Semantic (语义分析)              │
└─────────────────────────────────────┘
     ↓
┌─────────────────────────────────────┐
│  中间层 (Middleend) - 14.5K LOC 🔧  │
│ ├─ IR 构建 (将 AST → IR)           │
│ ├─ CFG 分析 (控制流)               │
│ ├─ DFA 分析 (数据流)               │
│ └─ 优化通道 (5 种优化)             │
└─────────────────────────────────────┘
     ↓
┌─────────────────────────────────────┐
│  后端 (Backend) - 18K LOC 📝        │
│ ├─ 指令选择 (IR → 机器指令)        │
│ ├─ 寄存器分配 (活跃性分析)         │
│ └─ 代码生成 (生成汇编代码)        │
└─────────────────────────────────────┘
     ↓
┌─────────────────────────────────────┐
│  链接器 (Linker) - 8K LOC 🔗        │
│ ├─ 目标文件处理 (ELF64)            │
│ ├─ 符号解析                        │
│ ├─ 地址重定位                      │
│ └─ 可执行文件生成                  │
└─────────────────────────────────────┘
     ↓
┌─────────────────────────────────────┐
│  运行时 (Runtime) - 12K LOC 🚀      │
│ ├─ 内存管理 (GC)                   │
│ ├─ 系统调用接口                    │
│ ├─ 并发基础                        │
│ └─ 标准库桥接                      │
└─────────────────────────────────────┘
     ↓
可执行程序 (.out)
```

## 🏗️ 系统架构设计

### 1. 前端架构 (16K LOC) ✅

**Lexer** (2K):
- Token 定义 (100+ 类型)
- 状态机扫描
- 位置追踪 (行号、列号)

**Parser** (8K):
- 递归下降解析器
- 优先级爬升 (表达式)
- AST 构造

**Semantic** (4K):
- 符号表管理
- 作用域处理
- 类型推导

**AST** (1K):
- 节点定义
- 树遍历
- 序列化

**测试** (1K):
- 21 个单元测试
- 集成测试
- 错误恢复测试

### 2. 中间层架构 (14.5K LOC) 🔧

**IR** (2K):
```
三地址码形式:
  x = y op z
  x = func(y, z)
  goto L
  if x goto L
```

**IR Builder** (3K):
- AST 遍历
- IR 生成
- SSA 构造

**CFG** (4K):
- 基本块 (Basic Block)
- 支配树 (Dominance Tree)
- 后支配树 (Post-dominance Tree)

**DFA** (3K):
- 活跃性分析 (Liveness)
- 可达定义 (Reaching Definitions)
- 用-定分析 (Use-Def)

**优化** (2.5K):
1. 常数折叠 (Constant Folding)
2. 死代码消除 (Dead Code Elimination)
3. 常数传播 (Constant Propagation)
4. 全局值编号 (Global Value Numbering)
5. 循环不变式移动 (LICM)

### 3. 后端架构 (18K LOC) 📝

**栈帧管理** (4K):

## 🔄 编译流程详解

```
源代码 (test.s)
     ↓ [Lexer]
Token 序列
     ↓ [Parser]
AST (抽象语法树)
     ↓ [Semantic]
带类型信息的 AST
     ↓ [IR Builder]
IR 序列 (三地址码)
     ↓ [Optimizer]
优化后的 IR
     ↓ [Instruction Select]
机器指令序列
     ↓ [Register Allocator]
分配了寄存器的指令
     ↓ [Code Generator]
汇编代码 (test.s.asm)
     ↓ [Assembler (gcc)]
目标文件 (test.o)
     ↓ [Linker]
可执行文件 (test.out)
     ↓ [Runtime]
程序输出
```

## 🚀 关键成功因素

1. **严格的语法规范**
   - 所有参数: `name type` (不用 `:`)
   - 所有指针: `type*` (不用 `&`)
   - 所有循环: `for` (不用 `while`)
   - 多返回值: `func() (T1, T2)` (不用 `result[T, E]`)

2. **完整的测试覆盖**
   - 单元测试每个功能
   - 集成测试每个阶段
   - 回归测试防止破坏

3. **增量编译**
   - 每个阶段独立构建
   - 每个阶段独立测试
   - 使用 git 追踪进度

4. **文档与注释**
   - 架构文档清晰
   - 代码自说明
   - 测试作为示例
