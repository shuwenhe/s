# P0.5d.5d.1.3a — Layout fact inventory and authority contract

Status: **authority boundary frozen; implementation open**. Scope: canonical S compiler under `src/cmd/compile/internal` at `main` commit `18246ecc6` (2026-09-18 audit). This document assigns ownership of facts and records current violations. It does not certify that the interfaces below already exist or that SysV classification is complete.

## Fact owners

| Fact | Sole decision owner | Consumer / boundary |
| --- | --- | --- |
| Resolved type identity, generic substitution, declaration and field order | Semantic/type resolution and monomorphization | Input to Layout Authority; textual type spelling is not identity |
| `sizeof(T)`, `alignof(T)`, padding, array stride | Layout Authority, parameterized by target data layout | Semantic queries, ABI Authority, lowering |
| Struct/tuple field offsets and aggregate physical structure | Layout Authority | ABI Authority and memory access lowering |
| INTEGER/SSE/MEMORY classification and eightbyte classes | ABI Authority, parameterized by target ABI | Call and return lowering |
| Parameter/result registers, sret mode and hidden sret argument | ABI Authority | Backend call and return lowering |
| ABI argument stack slot offsets, size and alignment | ABI Authority | Backend |
| Local frame slots, temporary spills and physical register allocation | Backend lowering, constrained by `TypeLayout` and ABI assignments | Instruction selection and frame emission |
| Machine instructions and relocations | Backend | Object code |

The distinction between an **ABI argument slot** and a **local spill slot** is deliberate. The former is observable at a call boundary; the latter is an implementation choice after ABI assignment.

## Frozen interface contract

The names below define the boundary, not current S syntax or an assertion that implementation exists.

```text
ResolvedTypeId = identity after name resolution and generic substitution
TargetDataLayout = pointer width, endianness, scalar alignment and aggregate layout rules

layout_of(ResolvedTypeId, TargetDataLayout) -> Result<TypeLayout, LayoutError>
TypeLayout = {
    type_id, target,
    size_bytes, align_bytes,
    fields: [{ field_id, offset_bytes, layout_id }],
    shape: scalar | pointer | array(element_layout_id, count, stride_bytes)
         | aggregate | union | opaque,
    abi_relevant_scalar_kind,
}

classify_signature(
    [{ type_id, layout_id }], [{ type_id, layout_id }], TargetABI
) -> Result<AbiSignature, AbiError>
AbiSignature = {
    argument_classes, result_classes,
    argument_locations, result_locations,
    hidden_arguments, stack_argument_area, return_mode
}

lower_call_or_return(AbiSignature, typed_values) -> machine operations
```

Required invariants:

1. `TypeLayout` is the single source of physical type facts. Its cache key includes resolved type identity and target data layout. ABI may inspect its fields and scalar kinds; it may not recalculate size, alignment, padding or offsets from a type name.
2. A layout result is valid only after generic substitution. Unresolved, recursive-by-value, unsupported or unsized types return a typed error. No `8`-byte fallback is allowed.
3. `AbiSignature` is the single source of call-boundary decisions. It records the actual target ABI, register classes and assignments, stack argument slots and return mode. Classification uses physical structure, not size alone. The same signature result serves both callers and callees.
4. Backend consumes `AbiSignature` and `TypeLayout` references for memory operations. It may choose local spills and instructions, but may not infer ABI mode from arity, string delimiters or a size threshold. Debug artifacts must serialize the same decisions used by lowering, or explicitly declare themselves non-authoritative diagnostics.
5. Target data layout and target ABI are separate inputs. An `amd64` layout does not imply one universal calling convention. ABI classification must identify the convention it implements; unsupported conventions fail explicitly.

## Boundary checks for the next implementation slice

1. Introduce resolved type identity and `layout_of` before routing ABI through it. Cover scalar, zero-sized, array, struct, nested aggregate and instantiated generic layouts for a named target. Verify field offsets, total size, alignment and array stride independently of ABI.
2. Change ABI input from `string[]` to typed layout references. Classify one actual target ABI, including mixed INTEGER/SSE aggregates, memory passing, stack slots and return/sret. Compare caller and callee assignments.
3. Route `.abi` and `.abi.emit` through that result and remove `abi_emit_aggregate_size_hint`, `param_count * 8` aggregate sizing, string-delimiter tests and duplicate index-based location rules. Preserve artifact versioning or update consumers deliberately.
4. Only then route actual call/return machine lowering through the same `AbiSignature`. A passing artifact test alone is not proof of this edge. Keep SSA integration and Stage1 convergence downstream of this boundary.

This audit searched the compiler-owned code paths cited above. It does not claim a complete scan of vendored/runtime layout code or a running end-to-end Stage1 proof.
