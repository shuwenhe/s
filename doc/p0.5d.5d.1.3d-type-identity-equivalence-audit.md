## 3. Desired identity equivalence contract

All rules from here onward are **desired contract**, not current implementation claims.

```text
CANONICAL TYPE IDENTITY INVARIANT

Within one canonical compilation identity domain D:

semantic-equivalent resolved types → same CanonicalTypeRef
semantic-distinct resolved types   → distinct CanonicalTypeRef
```

For admitted resolved types, define equivalence by the semantic keys below. Handle equality within D must implement exactly this equivalence. Assignment conversion, trait satisfaction, overload matching, equal size/alignment, equal numeric rank and identical diagnostic text are separate relations and cannot be used as interning equality.

| Admitted resolved form | Identity key / equivalence rule |
| --- | --- |
| Builtin | Builtin semantic tag. Separate tags for the E3 entries; no inferred aliases. `int` and `i64`, or `str` and `string`, remain distinct under this contract. Unit and never have their own tags. |
| Named struct, enum, trait | Resolved package identity plus the specific declaration identity, including declaration kind. Equal field shape or equal method sets do not merge different named declarations. Repeated imports of the same resolved declaration do not create new identities. |
| Raw pointer | Raw-pointer constructor plus child ref and any admitted identity-relevant pointer qualifiers. It remains distinct from both its child and a borrow reference. |
| Borrow reference | Reference constructor, mutability and child ref. Shared and mutable references are distinct. Extra qualifiers require defined semantics before admission. |
| Slice | Slice constructor plus element ref. |
| Fixed array | Array constructor plus element ref and evaluated nonnegative integer length. Equal accepted constant expressions with equal values give equal keys. Different lengths or child refs differ. |
| Tuple | Tuple constructor plus ordered child refs and arity. The empty tuple normalizes to unit; a distinct singleton tuple, if admitted by syntax resolution, retains arity one. Tuple and named `result` are not implicitly identified. |
| Function signature | Ordered parameter refs, ordered return refs and admitted semantic modifiers. Parameter names and function declaration names do not affect signature identity. A receiver is represented according to its resolved calling signature; bound method conversion is explicit. |
| Generic declaration | Resolved declaration identity. Its binders/constraints/body belong to the declaration record. A generic function declaration is a symbol, distinct from the type of its signature. |
| Generic parameter | Owning declaration/binder identity plus parameter ordinal. Spelling `T` is diagnostic metadata. A bound parameter can have identity while remaining non-concrete. |
| Named generic application | Generic declaration ref plus ordered argument refs, with arity and constraints validated. A concrete application contains no unbound parameter/inference variable. Non-generic named declaration and a zero-argument application, if both APIs expose them, must normalize to one representation. |
| Nested application | Apply the same rules recursively to children; `Outer<Box<int>>` keys on the canonical `Box<int>` child, not its printed name. |
| Map with complete semantic inputs | Map constructor plus ordered key and value refs. Bare `map` is incomplete and not admitted as a complete map type. |
| Channel with complete semantic inputs | Channel constructor, element ref and direction (send, receive, bidirectional). Conversion between directions does not merge identities. A label without these facts is incomplete. |

Function returns require one chosen representation: this contract uses an ordered result list, with zero returns distinct from one tuple-valued return unless source semantics explicitly desugar them to the same signature before construction. Variadic parameters, effects or explicit calling-convention modifiers cannot be discarded; when admitted, their resolved semantic tags enter the key. Target ABI classification and register choices never enter type identity.

Admission limits are explicit. Library-style `box/option/result/vec` forms must resolve to a declared generic identity, or to a separately specified intrinsic tag; their spelling alone cannot choose between the two. Alias declarations, anonymous aggregates, unions and unsupported modifiers are rejected at the canonical boundary until their semantic normalization is specified. This deferral does not merge them with an arbitrary builtin or named type. `unknown`, inference holes and incomplete `fn`/`map` labels cannot yield complete type identities. `nil` is contextual literal information until resolved to a target type; module bindings are not types. Error recovery may use a distinguished invalid handle, which is excluded from successful resolved-type equality and lowering.

## 4. Canonical construction and generic substitution

These are construction rules, not an S storage/API design:

```text
resolved semantic components
    → validate kind, child domain, arity, qualifiers and constants
    → normalize permitted semantic sugar
    → intern the complete semantic key in D
    → CanonicalTypeRef owned by D
```

Interning must return the existing ref for an equal key and a distinct ref for a distinct key. Hash equality alone is insufficient; collisions require full key comparison. Children must already refer to D. Missing facts produce an error or an explicitly incomplete semantic state, never a fabricated complete identity. Same-domain constructed keys are immutable once published.

Resolve named declarations and binders before resolving their bodies. Recursive nominal declarations refer to an already established declaration identity, so `Node` containing a pointer to `Node` does not require recursively hashing its entire field graph. Attach the resolved field graph to that declaration record without changing its identity. A declaration ref reserved for forward resolution is not proof that its body is complete. Duplicate declarations and failed completion cannot silently overwrite an existing type. Recursive value layout legality is a later question; unresolved declaration bodies cannot cross a successful concrete handoff.

Generic substitution maps binder refs to argument refs and recursively rebuilds only changed constructor nodes through the same interning authority. Substitution of `Box<T>` under `T → int` must reach the same ref as direct resolution of `Box<int>`. Renaming a binder's display spelling within the same declaration does not change its identity. Distinct generic declarations with identically spelled binders remain distinct. Alpha-equivalence of separate polymorphic function expressions is outside the admitted forms; a matcher/unifier must not reuse identity equality as a shortcut.

Semantic creates concrete applications when arguments are available there. Mono can request them when substitution becomes concrete, as frozen in 1.3c. Its function-specialization cache must eventually key on resolved callable declaration identity and ordered argument refs; generated symbol names are output metadata. Type identity and callable specialization identity are related keys, not interchangeable handles.

## 5. Registry ownership and lifetime

One canonical compilation context owns D: the resolved package/declaration graph, type interning authority and reachable type-definition records. This is a required ownership boundary, not a choice of map/vector/global variable implementation.

| Participant | Contract |
| --- | --- |
| Compilation context | Creates D before typed semantic resolution; destroys it only after all dependent IR and queries are finished. A process-wide unscoped singleton is insufficient. |
| Package loading/resolution | Supplies actual package identities, declarations and per-source resolution scopes; repeated imports share the same declarations. Import aliases do not create new packages. |
| Semantic | Resolves source types and publishes refs plus typed associations; owns source-resolution diagnostics. |
| Mono | Shares D, substitutes refs and requests canonical constructions. It must not create an independent identity cache from names. |
| MIR / SSA | Retain D through the enclosing compilation or an equivalent explicit owner. Preserve refs; any necessary new compiler type uses the same constructors. |
| Future Layout Authority | Reads definitions via refs in D. Physical layout belongs to separate target-keyed queries and cannot change type equality. |

Do not compare raw handles from different domains. Cross-compilation serialization must rebind semantic declaration/constructor records in a destination domain, through a specified import protocol. Printing and reparsing names is not such a protocol. Persistent numbering and incremental cache formats are outside this contract.

## 6. Propagation and order independence

| Edge | Current evidence | Required propagation |
| --- | --- | --- |
| Semantic → Mono | E4/E8: diagnostics followed by a `source_file` call. | Typed result carries D, declaration refs and refs for signatures, fields, resolved expressions/calls and generic binders. |
| Mono → Lowering/MIR | E6: source AST and string substitutions; item positions change. E7: structs collapse to `"struct"`. | Carry substituted refs and original declaration associations. Preserve the reachable field graph in D across erasure of AST structure. Item position or generated name cannot recover identity. |
| MIR → SSA | E7: locals/operands and SSA values/phis expose string type fields. This does not prove the pipeline is connected. | Renamed/copied values retain type refs. Phis require identical resolved incoming type refs after any explicit conversions; names and variable versions are not type identities. |

Source diagnostics and dumps may retain strings, but canonical consumers must operate on refs. Missing type data at a canonical handoff must be diagnosed. Existing bypasses remain observed gaps; marking a route legacy cannot count as proof that the canonical invariant covers the compiler.

```text
FORBIDDEN after canonical resolution:
TypeRef → display string → parse → reconstructed semantic identity
```

Order independence means that import traversal, type discovery, mono worklist order and constructor call order do not change the partition of resolved types into equivalence classes. Resolving the same already selected declaration twice in D must return the same ref. Declaration lookup cannot choose whichever same-spelled declaration was visited first; ambiguity is a resolution error.

Raw numeric ids may depend on allocation order. Across two fresh compilations of the same resolved program, the registries must correspond by semantic keys and preserve all equality/distinction relationships; the numeric ids need not match. Within one D, repeated insertion never changes or duplicates a published ref. If construction is parallelized, publication must enforce this same uniqueness rule. Package/declaration keys must not depend on a mutable merged-AST index; how those keys are encoded remains an implementation choice.

## 7. Unresolved choices and prerequisites

| Choice / gap | Requirement before implementation admits the affected case |
| --- | --- |
| Package/declaration key representation | Choose identities tied to resolved package/declaration objects, including duplicate/ambiguous declaration handling and retained per-source import scope. 1.3c's provenance gap is still open. |
| Ref and registry storage | Choose opaque-handle validation, domain association, interning lookup/collision handling, declaration completion and lifetime enforcement. Do not store display text as the identity key. |
| Typed result transport | Choose typed AST vs persistent side tables, with associations surviving mono item filtering/appending. 1.3c's `item_packages` gap is still open. |
| Source spelling normalization | Establish supported pointer/reference and prefix/suffix array/slice spellings at resolution. Array constant evaluation and rejection must yield semantic lengths. Do not assume E10 passes. |
| Function and binder detail | Retain full signature facts; decide supported modifiers, result syntax lowering and constraint transport. E1's `parse_where_clause` consumes text without retaining its clauses. Incomplete signatures cannot be interned as bare `fn`. |
| Intrinsic vs declared generic | Resolve ownership of `box`, `option`, `result`, `vec` and any library containers before admitting them; define any intended tuple/result or builtin aliases explicitly. |
| Forms beyond the core | Implement complete map/channel inputs before admission. Alias declarations, anonymous aggregates, unions and extra qualifiers need semantics before adding constructors. They currently follow the explicit rejection policy. |
| Entry coverage | Account for semantic-skip compiler entries recorded in 1.3c before claiming end-to-end enforcement. |
| Persistence/concurrency | Choose implementation mechanisms if needed; neither deterministic numeric ids nor a parallel registry is required for the first implementation. |

These open choices do not authorize a fallback to strings. Existing source inconsistencies and provenance gaps are recorded, not repaired in this audit.
