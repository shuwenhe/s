## 编译管道处理流程

### 1. 输入处理
```
Input File (.s)
    ↓
字符流规范化
    ↓
行/列位置记录
```

### 2. 词法分析 (Lexer)
```
字符流
    ↓ 状态机驱动
Token流
    ├─ Keyword: if, for, func, struct, ...
    ├─ Identifier: variable, function names
    ├─ Literal: 整数、浮点数、字符串
    ├─ Operator: +, -, *, /, :=, ==, ...
    ├─ Punctuation: (, ), {, }, [, ], ;, :, ...
    └─ Comment/Whitespace: 已过滤
```

### 3. 语法分析 (Parser)
```
Token 流
    ↓ 递归下降
AST 构建
    ├─ PackageDecl
    ├─ ImportDecl
    ├─ FuncDecl
    │   ├─ Receiver (可选)
    │   ├─ Parameters
    │   ├─ Returns
    │   └─ Body (BlockStmt)
    ├─ StructDecl
    │   ├─ Fields
    │   └─ Methods (存储为 FuncDecl)
    ├─ EnumDecl
    ├─ VarDecl
    └─ Statements
        ├─ ExprStmt
        ├─ IfStmt
        ├─ ForStmt
        ├─ WhileStmt
        ├─ BlockStmt
        ├─ ReturnStmt
        └─ SwitchStmt
```

### 4. 语义分析
```
AST + Symbol Table
    ↓ 类型检查
Type-checked AST
    ├─ 作用域解析：变量/函数定义
    ├─ 类型检查：操作符兼容性
    ├─ 方法查找：接收器方法
    ├─ 泛型实例化：具体化泛型参数
    ├─ 可达性分析：死代码检测
    └─ 生存性分析：变量定义使用
```

### 5. IR 构建
```
Type-checked AST
    ↓ 转换
中间表示 (IR)
    ├─ Function IR
    │   ├─ BasicBlock[]
    │   │   ├─ Instruction[]
    │   │   ├─ Terminator (Br/CondBr/Ret)
    │   │   └─ Predecessors/Successors
    │   └─ CFG 链接
    └─ 全局数据
        ├─ GlobalVar
        ├─ ConstantPool
        └─ DebugInfo
```

### 6. 中间层优化
```
IR (SSA 形式)
    ↓ 优化通道 (Pass)
优化后的 IR
    ├─ 常数折叠 (ConstantFold)
    ├─ 死代码消除 (DeadCodeElimination)
    ├─ 公共子表达式消除 (GlobalValueNumbering)
    ├─ LICM (Loop Invariant Code Motion)
    ├─ 指令合并 (InstCombine)
    └─ 内联 (Inlining)
```

### 7. 指令选择
```
优化后 IR
    ↓ SSA 规则匹配 (13,000+ 条规则)
架构相关指令序列
    ├─ x86-64: MOV, ADD, JMP, CALL, ...
    ├─ 寻址模式: [rax], [rbx+rcx*8+offset], ...
    └─ 指令组合: 融合 mul+add 等
```

### 8. 寄存器分配
```
架构相关指令
    ↓ 构建干涉图
虚拟寄存器 → 物理寄存器映射
    ├─ 干涉图着色 (Graph Coloring)
    ├─ Spill 处理 (溢出到栈)
    └─ 重新着色优化
```

### 9. 栈帧管理
```
寄存器分配结果
    ↓ Liveness 分析
栈帧布局
    ├─ 返回地址
    ├─ 保存的寄存器
    ├─ 本地变量
    ├─ 临时值
    └─ 调用参数空间
```

### 10. 汇编生成
```
栈帧布局 + 寄存器映射
    ↓ 代码生成
汇编代码 (.s)
    ├─ .section .text
    ├─ .globl main
    ├─ Prologue: push rbp; mov rbp, rsp
    ├─ 函数体: 指令序列
    ├─ Epilogue: pop rbp; ret
    └─ .section .data / .rodata
```

### 11. 目标文件生成 (Assembler + Linker)
```
汇编代码
    ↓ as (GNU Assembler)
目标文件 (.o, ELF)
    ├─ ELF Header
    ├─ Program Headers
    ├─ Section Headers
    │   ├─ .text (代码)
    │   ├─ .data (初始化数据)
    │   ├─ .bss (未初始化)
    │   ├─ .rodata (常量)
    │   ├─ .symtab (符号表)
    │   ├─ .strtab (字符串表)
    │   └─ .rela.text (重定位)
    └─ Content Sections
```

### 12. 链接 (纯 S 链接器)
```
目标文件 (.o)
    ↓ 符号解析 + 重定位
可执行文件
    ├─ ELF Header
    ├─ Program Headers
    ├─ 加载段：合并 .text, .data, .rodata
    ├─ 动态段：.dynamic (如需)
    ├─ 符号表 (剥离或保留)
    └─ 调试信息 (DWARF)
```

### 13. 运行时执行
```
可执行文件
    ↓ 加载器
进程内存空间
    ├─ Text 段 (代码, RWX → RX)
    ├─ Data 段 (初始化数据, RW)
    ├─ BSS 段 (未初始化, RW)
    ├─ Heap (malloc 分配)
    └─ Stack (栈帧)
    
    ↓ _start 启动代码
    ↓ main() 执行
    ↓ 系统调用 (read/write/mmap/...)
    ↓ exit(code)
```

## 性能优化策略

### 优化层次

| 层次 | 技术 | 预期收益 | 复杂度 |
|------|------|---------|--------|
| **1. 词法/语法** | 缓存、去重 | 5-10% | 低 |
| **2. 语义** | 增量检查、缓存 | 10-15% | 中 |
| **3. 中间层** | SSA 规则、GVN | **50-100×** | 高 |
| **4. 指令选择** | 模式匹配、成本模型 | 20-50% | 高 |
| **5. 寄存器分配** | 图着色、启发式 | 30-50% | 高 |
| **6. 栈帧** | 活性复用、对齐优化 | 10-20% | 中 |
| **总体** | **组合优化** | **100-500×** | 很高 |

### SSA 规则库 (13,000+ 条)

```
示例规则集:
└─ 算术优化 (1,044 条)
   ├─ x + 0 = x
   ├─ x * 1 = x
   ├─ x * 2 = x << 1
   ├─ (a + b) + c = a + (b + c)
   ├─ (a * b) * c = a * (b * c)
   └─ ...

└─ 寻址模式 (500 条/架构)
   ├─ a + (b * 4) → [base + index*4]
   ├─ a + b + c → [base + index + offset]
   └─ ...

└─ 架构特定 (2,500+ 条/架构)
   ├─ x86-64 特定指令
   ├─ ARM64 特定指令
   └─ ...
```

## 核心设计原则

### 1. 纯净的架构分层
- 前端：不依赖后端
- 中间层：仅依赖前端
- 后端：可独立于优化通道工作
- 链接器：独立存在

### 2. 测试先行 (TDD)
- 每个模块：先写测试，再实现
- 至少 80% 代码覆盖率
- 回归测试防止破坏

### 3. 文档即代码
- 类型和函数签名自说明
- 关键算法有文档
- 无内联注释（代码自说明）

### 4. 渐进式自举
- Stage 0: C seed （存在）
- Stage 1: 纯 S 前端
- Stage 2: 完整编译器
- Stage 3: 自编译验证

### 5. 性能优先
- SSA 规则库 13,000+ 条
- 每层都有基准测试
- 编译时间 < 100ms/file
