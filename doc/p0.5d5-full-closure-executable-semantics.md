## Q3 First Missing Executable Edge

Even granting successful parse, semantic check and monomorphization, the first
entry statement exposes a missing executable translation:

```text
cmd.main: args := std.env.args()
  -> ir.lower.dump_expr_stmt(stmt.let)
  -> "let args"                          initializer omitted
  -> make_entry_block_with_condition
  -> mir.eval(op="line", args=["let args"])
  + ownership reference observations    no call/result instruction
  -X-> executable call std.env.args, returned string[] bound to args
```

Evidence: `internal/ir/lower.s:588` maps statements through `dump_expr_stmt`;
at line 683 the let case renders only the name. At line 1003,
`make_entry_block_with_condition` stores these strings in `mir_statement.eval`
and invokes `mir_append_ownership_semantics_from_stmt`. In `internal/mir.s:841`
that helper visits the initializer. Its `expr.call` case at line 894 visits
callee/arguments for reference facts, but emits no executable call or return
binding. Thus ownership traversal does not restore the missing initializer.

This is the earliest source-order witness, not a predicted diagnostic or proof
that execution ever reaches the lowerer. A semantic error could occur earlier.

There is also an independent whole-program scheduling gap:

```text
lower_main_to_mir -> lower_package_to_mir
  -> lower_function_to_mir(picked)        exactly one selected body
  -> append "package.fn <name>"          other function names only
  -X-> executable body for std.env.args / print_usage / backend.build
```

`internal/ir/lower.s:337` counts functions, picks one, calls
`lower_function_to_mir` once at line 380, and adds names at line 392. There is
no reachable-callee traversal, function-to-graph map or executable package here.
Even the selected graph is not a complete lowering: let/assign render only
names, return renders `"return"`, and other paths retain source expressions.
Adding a loop over functions alone would therefore not close the first gap.

An alternate helper `mir.lower_function_graph:457` / `lower_block_graph:478`
adds ownership/drop events but also stores statement dumps. The modular build
call at `backend_elf64.s:298` invokes `ir.lower.lower_main_to_mir`, not an
all-functions driver around that helper. Its existence is not coverage proof.

## Q4 Source Dependencies

`backend_elf64.compile_writes:3127`, `compile_exit_code:3142`, and metrics first
call `execute_source_main:3172`, which finds the AST entry and executes its block.
`call_function_with_capture:3425` finds a source function, binds parameters and
executes its AST body. `find_function_in_source_graph:3489` may load imports;
`load_source_graph_for_use:4627` reads and reparses source. Expression dispatch,
member access, argument evaluation, constants and cleanup still use source/AST
representations. This is an attempted execution path, not evidence that it can
interpret this whole compiler successfully.

The MIR fallback does not supply the missing callee bodies:
`execute_mir_statement:3260` handles eval text through `emit_print_from_line`;
`execute_mir_graph:3201` follows a single graph and returns exit code zero at
its return terminator. Native emission receives computed writes and exit code,
not a table of all executable compiler functions. A constant return-42 fixture
alone cannot demonstrate whole-program compilation.

Source interpretation inside a faithfully compiled canonical Stage1 is allowed
as behavior of that compiler. Using source interpretation to conceal incomplete
translation of Stage1 itself is not evidence of executable closure coverage.
