PROBLEM STATEMENT

Script:         src/cmd/dist/source_closure.sh

Impact:         Blocks bootstrap build pipeline
Scope:          Affects shell-based dependency discovery phase

═══════════════════════════════════════════════════════════════════════════════

ROOT CAUSES (Ranked by Impact)
───────────────────────────────────────────────────────────────────────────────

RANK 1: Subprocess Overhead (13.7s = 68% of timeout)
├─ Current: while read line; do sed ... done (pipe spawns subprocess per line)
├─ Files:   8,146 source files in /src/cmd/compile/
├─ Calls:   8,146 × sed processes = 8,146 fork/exec syscalls
├─ Cost:    ~1.7ms per fork/exec × 8,146 = 13.7 seconds
├─ Proof:   strace -c shows 99.96% in wait4() (subprocess overhead)
└─ Fix:     Use xargs or single awk command (batch processing)

RANK 2: O(n²) Deduplication (6s = 30% of timeout)
├─ Current: for each file: grep -qxF "$path" "$seen" >> "$seen"
├─ Algorithm: Linear scan of growing file for each new entry
├─ Complexity: n=1,603 files → 1+2+3+...+n = n(n+1)/2 = ~1.3M line scans
├─ Cost:    1,300,000 scans × 0.005ms = 6+ seconds
├─ Proof:   Algorithm complexity analysis + timing measurements
└─ Fix:     Use awk associative array (in-memory hash table)

RANK 3: Redundant Lookups (6s = secondary impact)
├─ Current: resolve_module_fallback() calls awk for each import
├─ Calls:   4,000 module lookups × 1.5ms per awk process = 6s
├─ Algorithm: awk -v pkg="$module" scans 8,146-line index each time
├─ Cost:    O(n × m) where n=4,000 lookups, m=8,146 index lines
└─ Fix:     Preload package index once into awk associative array

FIX 1: Batch Package Extraction

Priority:       HIGH (highest impact: -13.6 seconds)
Complexity:     LOW (~30 lines)
Risk:           LOW (isolated, reversible)
Time:           1 hour

LOCATION: src/cmd/dist/source_closure.sh, Phase 1 (lines ~25-35)

CURRENT CODE:
  # Package extraction via subprocess
  find src -name '*.s' | while read source_path; do
    package=$(basename "$source_path" .s)
    # ... process each file ...
  done

NEW CODE:

  find src -name '*.s' | xargs -I {} basename {} .s | sort -u > "$packages_tmp"
  # ... continue with batch processing ...

BEFORE/AFTER:
  Before: find src -name '*.s' | wc -l  → 8,146 files
          while read loop creates 8,146 subprocesses
          Time: 13.7s
  After:  xargs creates ≤4 subprocesses (parallelism limit)
          Time: 0.1s

FIX 2: Hash-Based Deduplication
───────────────────────────────────────────────────────────────────────────────
Priority:       HIGH (second highest: -5.4 seconds)
Complexity:     LOW (~40 lines)
Risk:           LOW (algorithm change, no output change)
Time:           1 hour
Expected Gain:  6-10x speedup (6s → 0.6s)

LOCATION: src/cmd/dist/source_closure.sh, Phase 3 (lines ~200-210)

CURRENT CODE:
  # O(n²) deduplication via grep on growing file
  while read source_path; do
    if ! grep -qxF "$source_path" "$seen_file"; then
      echo "$source_path" >> "$seen_file"
    fi
  done

NEW CODE:
  # O(1) deduplication via awk associative array
  awk '
    BEGIN { split("", seen) }
    {
      if (!($0 in seen)) {
        seen[$0] = 1
        print $0
      }
    }
  ' input_file > output_file

BEFORE/AFTER:
  Before: grep -qxF scans growing file
          n=1,603 files → 1.3M line scans
          Time: 6+ seconds
  After:  awk hash lookup is O(1) per file
          n=1,603 files → 1,603 lookups
          Time: 0.6s

TEST COMMAND:
  $ time bash src/cmd/dist/source_closure.sh src/cmd/compile/main.s
  # Should see: Phase 3 complete in <1s

FIX 3: Memoized Module Resolution (OPTIONAL)
───────────────────────────────────────────────────────────────────────────────
Priority:       MEDIUM (optional, bonus: -2-6 seconds)
Complexity:     LOW (~20 lines)
Risk:           LOW (preload pattern is standard)
Time:           1 hour
Expected Gain:  6-10x speedup on module resolution

LOCATION: src/cmd/dist/source_closure.sh, resolve_module_fallback() function

CURRENT CODE:
  resolve_module_fallback() {
    local module=$1
    awk -F '\t' -v pkg="$module" '$1 == pkg {print $2; exit}' "$packages_index"
  }
  # Called 4,000 times, each awk scans 8,146 lines

NEW CODE:
  # Preload index once into memory
  declare -A package_cache
  while IFS=$'\t' read name file; do
    package_cache["$name"]="$file"
  done < "$packages_index"
  
  resolve_module_fallback() {
    local module=$1
    echo "${package_cache[$module]}"
  }
  # Called 4,000 times, each lookup is O(1)

BEFORE/AFTER:
  Before: 4,000 × awk processes × O(n) scan = 6s
  After:  Load index once O(n), then 4,000 × O(1) lookups = 0.6s
  Net:    -5.4s

QUESTIONS & TROUBLESHOOTING
───────────────────────────────────────────────────────────────────────────────

Q: Output differs after applying Fix 1 - what went wrong?
A: Likely issue: Phase 1 extraction differs. Check sorting/dedup in batch command.
   Solution: Ensure xargs pipeline maintains order of original find output.
   Verify: diff <(sort baseline.txt) <(sort fixed.txt) should be empty.

Q: Fix 2 (awk hash) is slower than expected
A: Likely issue: Large closure causing awk associative array overhead.
   Solution: Profile with M0_DIAGNOSTIC_TOOLS.sh dedup to measure actual speedup.
   Note: Fix 2 should be 6-10x faster on 1,603 files.

Q: Performance still >5 seconds after Fix 1+2
A: Likely issue: Didn't apply both fixes, or Phase 2 filter is bottleneck.
   Solution: Verify both fixes are applied. Run diagnostic.
   Plan: Consider Fix 3 (memoization) if needed.

Q: Closure file has different number of lines
A: CRITICAL - Output has changed! This means implementation error.
   Solution: Rollback immediately, review Phase 1/2/3 logic.
   Debug: Run M0_DIAGNOSTIC_TOOLS.sh closure to identify divergence point.
